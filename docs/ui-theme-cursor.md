# 显示切换中的光标修复

2026-10-11。最终提交与部署状态见[UI发布记录](ui-release-20261011.md)；下方验证段保留各轮当时状态。

## 最终行为

- 单击“显示：XX”后，在切换快照生成前同步目标主题光标：使用目标主题的 `--ink` 与标签 `--accent`。
- 用户明确否决切换专用双色边缘；最终没有额外描边。保留8px圆点、38px圆环、2px基础线宽与既有惯性／档位缩放。
- 光标在独立的过渡伪层内绘制，位于 nav 快照上方，不受正文径向裁剪影响；结束后恢复普通页面的反相光标。
- 保留450ms径向揭示、旧显示切换降级、MENU与滚动条交互。触屏不生成过渡光标帧。

## 证据与实现

修复前的真实鼠标与截图像素用例复现：光标DOM坐标已到nav区域，但与背景实绘对比度仅1.03:1。普通光标包含在root快照内，nav使用独立快照；普通DOM的z-index无法控制过渡伪层内的次序。

只给光标独立命名不足以跨引擎解决问题：零尺寸容器、实时快照更新与反相混合均出现绘制差异。最终在独立 `k-cursor` 过渡group中，以SVG背景绘制现有GSAP点／环／标签坐标。其group明确使用normal混合，避免再次继承原DOM的difference。只在ready后更新帧，静止帧内容相同时不重写；主题应用回调同步绘制新颜色，旧／新光标快照隐藏以免残影。

回收包括finished、ready失败／250ms看门狗、启动抛错、重复切换与pagehide。停止标记禁止已取消切换的晚到回调重新写入SVG；新切换接管旧回收。Chromium实测在快照期间 `elementsFromPoint` 可能仅返回html：未知命中保持当前光标档位，结束后用最近真实指针坐标重新命中，静止指针也恢复正确悬停状态。

实现：`src/client/motion.ts`、`src/styles/kinetic.css`。新增用例：`tests/e2e/theme-cursor.spec.ts`。

## 2026-10-11 18:11：光标自身切换动效

用户明确调用animate、animation-vocabulary，要求主题切换中的光标更灵动。采用 **Squash & stretch** — “Deforming an element as it moves to convey weight, speed, and flexibility.” 目的为偶尔切换显示模式的反馈／状态指示。

圆环100ms轻压成斜椭圆（scaleX1.14、scaleY0.86、深色-12°／浅色12°，power3.out），随后180ms以back.out(1.7)轻微越过终态再回到圆形。总时长读取既有--motion-normal（280ms）。中心点、颜色即时切换、语义标签及既有鼠标跟随保持，不添加双色边缘。不是物理弹簧求解。

定位／语义缩放保留在原圆环外层，新增内层只承担视觉形变，避免直接缩放／旋转鼠标的平移坐标。VT绘制帧读取同一内层姿态生成SVG矩阵；原生ready后开始，缺VT时用同一DOM动效。连续触发杀掉旧时间线但保留当前姿态，再从当前值接管；完成／离开／失焦／pagehide回收，1000ms原生兜底与强制clearProps防止暂停父时钟后复活。旧cursor启用门控不改，触屏不生成自定义光标。

新增真实浏览器逐帧断言先红（形变比例约1），实现后验证椭圆比例>1.15、回弹比例<0.995、形变中心与定位中心偏差<0.5px；覆盖连续切换、暂停后回收、nav上下往返、目标主题RGB、旧反相对比度、MENU及两种滚动条拖拽。最终联合五配置26通过、14项手机不适用跳过（1.1m）；check95文件0错误／0警告、2旧提示，build66页、Node301/301和diff检查通过。

初轮更宽联合45通过、14跳过、1次Firefox单像素颜色差26未达断言；原因未确定。补充失败状态输出后隔离复验2/2、最终联合中的同一用例也通过，未把重试写成确定根因修复。原显示切换VT四组用例在初轮五配置全过。本轮无真机、线上或FPS结论，未提交／部署。
