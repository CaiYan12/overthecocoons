## 实施前已核实的现状

- 首页与来源页使用全站导航，包含时间线、来源、关于、原则、隐私五个入口。
- `src/components/Longform.astro` 在关于、原则、隐私页使用本页目录替换全站导航，没有渲染 `KNav`。因此左栏的时间线、来源入口不存在，并非被目录遮挡或链接点击失效。
- 线上首页进入关于页复核：左栏全站导航不存在，本页目录有六项；MENU 和页脚仍提供时间线入口。
- 关于、原则各有六项目录，隐私有五项。全站导航已有当前页面状态；本页目录目前没有当前章节高亮的客户端实现，不能把历史注释视为已实现功能。
- 现有断点：桌面（至少 1200px 宽）三栏；平板（768–1199px）隐藏全站左导航与长文目录；手机（最多 767px）隐藏左导航，将目录放到正文上方。MENU 是各页共同的跨页入口。
- 按现有字号、行高和间距估算，五个全站入口、返回主站及六项目录叠加约需 571px 高；600px 高的桌面窗口在顶部留出 100px 后预计放不下。该数值用于讨论，尚非浏览器实测。

用户选择 A：五个全站入口顺序固定，本页目录单独放在下方。右侧来源／状态信息继续采用现有结构。

## 已确认的响应式决定

### Q2：常规桌面短屏仅滚动本页目录

用户选择只让本页目录内部滚动：优先让五个全站入口始终可见，章节区需要时滚动。

### Q3：沿用现有宽度断点

用户选择沿用现有入口方式：平板通过 MENU 换页；手机通过 MENU 换页，本页目录放在正文上方。桌面三栏宽度条件保持至少 1200px，不为本次导航调整改动原有宽度断点。

### Q4：极矮桌面窗口允许整栏滚动兜底

用户选择允许整个左栏滚动兜底。实施复核发现 430px 左右的窗口虽然能容纳全站入口，但剩余空间不足一行目录；用户进一步确认将条件扩展为「全站导航与至少一行可操作目录无法同时容纳」。两者均能容纳时仅目录内部滚动；不足时整栏滚动，保证两组入口都能到达。

## 实现验收条件

- 关于、原则、隐私三页在桌面左栏都有时间线、来源、关于、原则、隐私五个全站入口，保持相同顺序；当前页面继续使用全站导航现有的激活状态。
- 本页目录单独在全站导航下方，章节数量与标签保持原内容，链接继续跳转到当前页对应章节。
- 普通桌面与常规短屏：阅读或滚动目录不使五个全站入口滚出左栏可见区域。
- 极矮桌面：所有全站入口与目录项均可滚动到达，不被永久裁切；键盘 Tab 能依次到达并显示焦点。
- 保持 1200px / 768px 宽度断点策略：平板经 MENU 换页，手机经 MENU 换页且目录在正文上方；原页脚入口继续可用。
- 手机目录的首个章节入口避开固定页头；桌面跳到末章后，全站入口仍可点击。
- 保持锚点的无 JS 可用性，不为此功能增加第三方依赖或存储。
- 浏览器验收覆盖三页；桌面至少检查 1440×900、1440×600，以及全站导航本身无法完整容纳的极矮窗口；窄屏检查 1024×768、390×844。高度阈值须依据实际布局验证，不把前文估算当作实现尺寸。

## 本地实现与验收

- `Longform` 复用 `KNav`，按全站导航／本页目录分组；三页均保留当前页状态、返回主站和原章节锚点。
