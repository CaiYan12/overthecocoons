## 项目与产品目标

- 项目：跳出茧房 Over the cocoons。
- 主目标：帮助读者接触平常不会关注的领域和来源，拓宽视野。
- 次目标：日常资讯浏览。
- 网站提供公共时间线，本站不根据个人行为做推荐或排序，所有人默认看到同一份数据和顺序。
- 不登录、不广告、不收集行为统计、不记录阅读历史，不人工挑选、排序或推荐单条内容。
- 来源准入、移除和明确规则下的内容治理允许人工维护。
- 来源本身可能已经过热点筛选；不得将“本站无个性化”描述为“上游没有算法筛选”，也不得宣称已保证消除信息茧房。

## 首版范围

一个来源即可正式公开，后续逐步增加来源。

MVP 包含：

- 公共时间线及内容卡片，每页最多 20 条；显式分页，不使用无限滚动。
- 单选主题筛选与“全部”入口，先筛选全部保留内容，再分页；刷新重置筛选状态。
- 来源页。
- 关于、原则、隐私信息。
- 图片显示与本站占位图。
- 每日自动更新及手动触发。
- 来源提交 GitHub Issue 模板。

首版不包含随机漫游、搜索、RSS / JSON Feed 输出、多源对照、用户系统、评论、点赞、收藏、个性化推荐、广告、复杂 AI 摘要。增强功能留待后续。
视觉风格及具体布局在设计阶段另行对齐；本轮未选定颜色、字体或页面样式。
原文的移动端可用、子路径资源正常、图片异常处理等验收目标保留；Lighthouse 四项 > 90 为原文目标，不能将未执行的检查宣称通过。

## 领域术语

| 术语 | 含义 |
| --- | --- |
| 公共时间线 | 使用同一站点数据快照与排序规则展示的时间线，不做个人行为排序 |
| 来源 | 原始内容/热点平台；与第三方 feed 服务提供者区分 |
| Feed 服务提供者 | 提供订阅转换或聚合服务的主体，不自动视为原始内容作者 |
| 热点线索 | 可通往百度搜索结果的主题条目，不称为原始新闻文章 |
| 发布时间 | 可核验为原始内容发布时间的时间；未知语义的 feed 日期不能充当它 |
| 首次收录时间 | 本站第一次接受该条目的时间，重复抓取不得刷新，须跨构建保留 |
| 排序时间 | 可靠发布时间优先；缺失时使用固定首次收录时间 |
| 数据快照时间 | 生成当前成功站点数据的时间，作为保留窗口的计算基准 |
| 来源默认主题 | 分类字段缺失时的来源级标签，非逐条内容推断 |
| 去重 | 合并同一内容的重复收录，不按相似标题合并独立报道 |

## 数据、排序与保留

- 通用规则：可靠发布时间优先；无法核实发布时间时，使用固定首次收录时间，并在卡片上明确标为“收录时间”。
- 当前百度源的 feed 时间语义未知，首版全部使用本站首次收录时间。
- 时间线按排序时间倒序；同一批次时间相同的条目必须有稳定顺序，不按热度重排。
- 同一条目的重复抓取不能让它重新成为“最新”；首次收录记录需要跨每日构建保存。
- 只保留最近 7 天，以成功生成站点时的数据快照为基准。实现采用滚动 7 天窗口；不能按每个访客的浏览器时间产生不同默认结果。
- 可靠发布时间条目按发布时间计算窗口；无可靠发布时间条目按固定首次收录时间计算窗口。
- 持续积累仍在窗口内的已收录内容，不能每天仅用 feed 当前返回列表覆盖全部历史。
- 合并同一内容的重复收录；保留不同来源的独立报道。MVP 不做标题相似度去重。
- 热点条目的稳定身份和重复判定须根据实测 GUID / 链接规则在实现阶段验证；不能把搜索链接称为新闻原文唯一标识。

## 摘要、图片和标签

- 摘要优先使用源摘要。
- 源没有摘要时，从源提供的正文截取纯文本；最多 300 字。
- 两者都没有时，不编造摘要，保留其他条目信息。当前百度 feed 不提供全文，因此没有额外正文补抓。
- 不直接渲染不受信任的来源 HTML。
- 允许加载来源图片；不转存、不裁剪、不通过图片做推荐，按原文约束懒加载与处理外链引用。
- 没有图片、图片加载失败或来源明确禁止外链时，保留图片区域并显示本站占位图；明确禁止时不请求该图片。
- 当前首源没有图片字段，因此首版该源使用本站占位图，不主动从搜索结果取图。
- 固定主题词表：新闻、科技、文化、科学、社会、经济、环境、健康、教育、艺术、哲学。
- 优先按公开映射规则处理源明确提供的文章分类；缺失时用来源默认主题，不凭标题猜测分类。
- 当前首源默认同时标为“新闻”“社会”。
- 首版接受全中文；中文约 90%、外语约 10% 只作后续多源方向，不删减条目凑比例。
- 来源地区和语言为来源配置的静态信息；不使用浏览器语言改变内容顺序，不自动推断政治倾向。具体来源信息须核实后填写。

## 隐私与商业内容

- 本站不采集行为数据，不引入第三方统计、广告、社交追踪插件或第三方字体 CDN。
- 不设置追踪、不写阅读历史，不因用户行为调整内容。
- 允许源图片等外部资源；隐私说明应准确区分本站不追踪与外部资源请求。
- 不人工精选单条内容。
- 自动排除来源明确标记的广告、赞助或商业推广；规则公开。
- 不能把“仅排除明确标记”写成“上游所有内容均无商业关系”。当前源没有可靠商业标记，识别能力受其数据限制。
- 默认不展示热度、点击量或推荐指数。

## 更新与异常行为

- 每日北京时间 08:00 触发一次自动更新，保留手动触发入口；触发计划不等于保证正点完成部署。
- 某来源抓取失败：保留其仍在本次数据快照窗口内的旧内容，其他成功来源继续更新，并显示数据时间和来源异常。
- 整个更新/构建流程失败：保留上一次成功页面，以其快照时间解释 7 天窗口，并显示上次成功更新时间。
- 必须区分本次运行时间、上次成功抓取时间与成功数据快照时间，不能把失败运行标成成功更新。
- 静态旧页面无法预知其部署后发生的失败；具体异常提示与运行监测方式须在 SPEC 中明确，并做端到端验证，不能凭空承诺动态故障提示。
- 内容为空时显示真实空状态，不伪造条目或凑足 20 条。
- 页面明确为每日更新的快照，不宣称本站实时刷新。
