# 时间线层级与时间呈现口径

2026-10-06，用户在 P1 版式诚实化规格（#16）grilling 中逐项裁定以下语义口径：

**取消位置型头条档（w1）**：时间线内条目不再设 76px 位置型头条档，视觉层级由内容事实驱动（是否提供摘要、日内交替节奏），大字时刻由日组头承担。理由：条目顺序实为首次收录时间倒序与稳定 ID 确定性次序，位置序头条落在的是哈希序偶然条目，外观却像编辑挑选，与「不人工挑选、排序或推荐单条内容」约束下的呈现诚实性冲突。

**日组头规则驱动**：同日条目的首次收录时间分钟全相同时，日组头显示「批次 hh:mm · N 条」，条目行省略时间；一旦出现不同分钟，条目行显示各自时间（北京时间）。理由：实测数据每日仅一个收录时刻，逐条重复同一分钟是冗余；规则化使未来多源或真实发布时间接入时无需重构呈现层。

**NOW READING 保留 n/300**：阅读位计数保留，延续既有 UI 票 #11 无聚焦归位 `--` 的裁定，仅去除版画上的出血大序号。理由：有限可数是数据快照区别于无限信息流的品牌信号；该计数是位置指示，不是排名。

**快照口径**：可见时间一律换算为北京时间呈现，`<time datetime>` 保留 UTC；「北京时间」字样仅在 HUD 快照行标注一次；快照文案为「快照 · 每日更新 · {日期 时间}」，不写死更新钟点。理由：GitHub Actions 定时触发是尽力而为，实测延迟 4–5.3 小时，写死钟点构成不可兑现的表述；时区方案与 P0 一致。

以上为纯语义与呈现口径裁定，不改变排序（仍是首次收录时间倒序）、7 天公开保留窗口与无个性化约束；对应版式实施属 P1 其余票项。
