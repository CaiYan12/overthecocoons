# MVP 架构对齐结论

日期：2026-10-03。上轮按用户要求停止讨论并归档；本轮用户明确要求继续未决对齐，从 MVP-Q13 开始，不重问 Q1–Q12。本文记录已明确的决定；尚未确定事项与工程建议另列，不当作已批准实现。
基线：[产品对齐](product-alignment.md)、[UI 对齐](ui-alignment.md)、[设计规范](ui-design.md)、[领域术语](../GLOSSARY.md)。

## MVP-Q1：公开保留与技术历史

用户确认：当前网站和当前内容数据只保留最近 7 天；允许技术备份或版本历史留存，但不提供站内旧内容阅读入口。
这不是“任何旧副本均已彻底删除”的承诺。首次收录身份记录与公开可读条目内容需要分别定义。

跨日状态位置与条目身份已由 MVP-Q2/Q4/Q5 确定；备份/历史与当前快照的具体文件分离方式仍是工程建议。

## MVP-Q2：权威数据位置

用户选择独立数据分支，拟命名 `data`，保存首次收录记录、当前 7 天条目及采集状态；`main` 保存代码。自动写入发生在以后启用的更新工作流中，本轮不创建或推送分支。
详见 [ADR-0001](adr/0001-authoritative-ingestion-state.md)。后续待定写入时机、并发、构建和部署之间的事务边界。

## MVP-Q3：首次收录与发布分离

用户确认：条目采集校验通过并成功保存权威状态即算收录。即使当次构建或部署失败，后续成功发布时仍保留最初收录时间，不能将重试发布时间当作新收录时间。
这要求保存收录状态与发布站点分开处理；构建/部署失败保留上一次成功页面，但不回滚已经保存的首次收录事实。

## MVP-Q4：首源身份规则

用户选择来源 ID + GUID 为主身份。不凭相似标题或相同百度搜索词合并不同 GUID；缺失或发生冲突时隔离异常条目，保留已有可信数据，不自动用链接重建身份。
GUID 长期稳定性尚无证明，此规则是本站采用的身份策略，不是对上游行为的保证。内容更新与关键词冲突规则已由 MVP-Q5 明确，具体提取与比较算法仍须固化。

## MVP-Q5：内容更新与冲突

用户确认：同一来源 + GUID 的搜索关键词一致时，可更新标题与摘要，但保持首次收录时间；搜索关键词改变时视为身份冲突，隔离新输入并保留旧条目。
标题清理值不等同于搜索关键词；当日实测已有二者空白差异的样例。关键词的提取与精确比较规则将在 SPEC 固化，不能凭标题猜测。

## MVP-Q6：静态详情与过期页面

用户选择为当前条目预生成 `/items/<id>/` 静态详情页面；条目过期时不再生成对应页面，由自定义 404 显示“条目已过期或不存在”及返回入口。
这是拟定路由，不是现有页面。实际 URL 还须带 `/overthecocoons/` 部署基路径，GitHub Pages 的项目 404 行为须在发布验收验证。

## MVP-Q7：渐进增强与降级

用户选择标题、简介、详情和基本页面导航在无 JavaScript 或交互脚本加载失败时仍可读，并补充简版条目目录；筛选、动态分页及菜单动画可降级。
实现必须先提供可读 HTML，再在交互初始化成功后增强；不能先隐藏全部内容却依赖脚本恢复，也不能仅用 noscript 覆盖“JS 开启但脚本失败”的场景。

## MVP-Q8：采集触发与代码构建分离

用户选择仅定时/手动更新采集来源；main 推送只读取已保存的 data 状态，进行检查、构建与部署。代码构建不能隐式重新抓源或改写首次收录事实。
本地 build 与刷新数据命令也应分别定义，避免开发时每次构建造成未经预期的外部请求。

## MVP-Q9：来源失败与发布失败区分

用户选择在已有旧数据仍可校验时，来源获取失败也可继续构建：保留窗口内旧条目、清理过期内容、明确来源失败和上次获取成功时间。不把本次尝试标为获取成功。
构建或部署本身失败时，保留上一次成功网站。没有可信旧数据的首次失败，不能伪造可用快照；首次初始化的边界将在实施计划明确。

## MVP-Q10：包管理器与运行时

用户选择 Node 24.18.0、pnpm 10.26.2 和 pnpm-lock.yaml；本地与 CI 固定同一版本，严格按锁文件安装。本轮尚未安装依赖或生成锁文件。
当日只读检查已确认本机版本、Node 对应官方发行记录及已查依赖的声明范围；这不是安装、构建或测试成功证明。

## MVP-Q11：测试组合

用户选择 Node 内置 test runner 测数据规则、Playwright 1.63.0 测真实浏览器行为与布局。手机视口模拟和手机实机验证必须分别报告。
Node 的 TypeScript 类型擦除不提供类型检查；实施中还须运行独立类型检查。当前未安装 Playwright 或浏览器，也未运行测试。

## MVP-Q12：内容变化后的阅读位置恢复

用户确认：保留主题，尽量按原条目定位；条目不存在时将页码限制在有效范围并提示内容已更新。不能承诺内容变化后像素级恢复原位置。

## MVP-Q13：权威状态初始化与损坏恢复

用户确认两点：

- 首次 data 分支初始化采用独立手动入口（GitHub Actions 手动 workflow_dispatch 或本地命令）；定时任务发现无权威状态时报错停止，不自动初始化，保证首次身份台账是明确的人为动作。
- 日常更新发现权威状态缺失或校验损坏（如 state.json 与 manifest.json 摘要不符）时，该次运行立即终止：不写新权威版本、不生成新快照、不发布；线上保持上一次成功站点。恢复由人从 data 分支 Git 历史或备份核对后执行，台账绝不自动清空重计。

## MVP-Q14：身份台账保留寿命

用户确认：身份台账无限保留。台账只存身份依据（稳定 ID、来源 ID、原 GUID、首次收录时间、搜索关键词指纹），不含可读正文；条目过期后记录保留，防止同一 GUID 再次出现被当作新条目重计首次收录时间。台账是技术身份记录，不是站内阅读入口，与 Q1 的 7 天公开窗口不冲突。

## MVP-Q15：稳定详情 ID 算法

用户确认：稳定 ID 为对“来源 ID + 分隔符 + 原始 GUID”字符串的完整 SHA-256，输出完整 64 位十六进制，不截断。GUID 保持原始字符串参与摘要，不转数字、不改大小写。这是详情页 URL 与身份台账主键，生成后不可变更。

## MVP-Q16：data 分支文件契约

用户确认：三文件分离，同一 Git 提交保存全部三个文件，避免身份台账与内容错配。

- `state.json`：schemaVersion、状态时间、身份台账、来源尝试/成功/异常状态。
- `items.json`：当前 7 天窗口内的已接受条目内容。
- `manifest.json`：前两个文件的摘要与生成信息，用于损坏校验。

台账无限增长与每日内容变更分离，diff 可读，损坏时能定位是台账还是内容的问题。

## MVP-Q17：并发写入冲突

用户确认：写 data 前记录读取时的提交版本，写回时若分支已前进，该次运行失败并明确报告冲突，等下次定时/手动重试；不自动合并重试，不 force push，不采用“最后写入者覆盖”。代价是冲突日当次更新延迟，收益是不覆盖并发期间的首次收录记录。

## MVP-Q18：辅助备份

用户确认：不另建备份机制，data 分支 Git 历史即唯一可信恢复来源，与 Q13b 的人工恢复路径一致。仓库整体丢失属于 GitHub 账号层风险，不在 MVP 范围内。

## MVP-Q19：搜索关键词提取与 wd 缺失

用户确认：

- 提取规则：从目标链接解析 URL 查询参数取 `wd`；多个 `wd` 取第一个并记录原始值。
- 比较规则：解码后字符串精确相等才算关键词一致；不 trim、不归一化词内空白、不从标题反推。
- 缺失处理：目标链接缺失 `wd` 的条目照常校验收录与展示（身份仍是来源 + GUID），关键词指纹记为空并标注，后续该 GUID 重新出现时跳过关键词冲突检测。当前实测 100 条均含 `wd`，此为边缘情况。

## MVP-Q20：隔离条目的公开可见度

用户确认：公开列出隔离条目。身份冲突、字段校验失败等被隔离的异常条目在来源页列出，供公众监督；不采用“仅计数不列条目”方案。

约束（由既有决定派生）：

- 隔离条目必须明确标注隔离状态与原因类别，不得与正常时间线条目混淆，不得宣称其内容已通过校验。
- 隔离列表同属公开可读内容，随 7 天公开保留窗口滚动；条目移出展示后，身份与异常记录仍按 Q14 保留在台账。
- 展示字段与安全输出方式见 Q22 与架构文档。

## MVP-Q21：常规工程方案固化

用户确认以下八项按建议固化为实施基线，实施时如与实际依赖/环境冲突再回到此处置新确认：

1. 单次运行内源获取最多 2 次尝试、短退避；仍失败按 Q9 降级。
2. 构建 checkout 固定的 data 提交并记录到产物元信息。
3. 目标链接仅接受 http/https，其余进异常隔离。
4. 客户端状态集中项目命名空间；切换主题重置页码；刷新/新访问重置。
5. 显示偏好用项目专属 localStorage key，实施时定名。
6. 路径 `/items/<64hex>/`，全部经 `/overthecocoons/` 基路径；404 真实验收留发布闸门。
7. 摘要优先源 contentSnippet，纯文本化后截断 300 字。
8. 公开快照内容版本仅随可读内容/窗口变化递增，排除仅尝试时间变化；隔离列表变化同属公开内容，一并计入。

## MVP-Q22：隔离条目的公开展示字段

用户确认：每条隔离记录公开展示四项字段——原始标题、目标链接、隔离原因类别（如身份冲突/字段校验失败/协议不合法）、隔离时间。足以监督隔离是否被滥用，不额外复制摘要等更多未校验内容。展示为纯文本安全输出，明确标注隔离状态，不与正常时间线条目混淆。
