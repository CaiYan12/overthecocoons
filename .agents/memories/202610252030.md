# 2026-10-25 分页跳转后 HUD/视差失效诊断与修复（已上线并验收）

## 症状与根因（全部实测确认，证据在 .snapshot/debug-pager-hud/）

- 线上与本地 fixture（66 页）都能复现：客户端分页跳转后 ①NOW READING 恒 `--`（列表节点激活 ScrollTrigger 死）②Hero 视差 scrub 冻结在跳页瞬间值；全局进度（start:0/end:"max"，无元素位置）不受影响；无 console 错误、未整体降级。
- 根因：`kinetic.css:55 html{scroll-behavior:smooth}` 下，ScrollTrigger 3.13.0 `_refreshAll` 的「写内联 scroll-behavior:auto → 滚到 0 → 测量 → 恢复」在 Chromium 失效——**内联样式写入未经 flush 即被紧随的 scrollTo 解析，浏览器仍按 smooth 异步动画执行**；同步测量发生在旧滚动位置而缓存滚动值已写 0，所有元素位置触发器 start/end 整体偏移 −(刷新时滚动值)。微实验（probe-micro.mjs）：内联 auto 后不 flush 的 scrollTo(0,0) 停在 3000；读一次 offsetHeight 或 pageYOffset 后即瞬时。
- 任何滚动 ≠ 0 时的 `st.refresh()` 都会损坏（主题切换/来源筛选/分页/resize 同源）；e2e 此前没抓到是因为夹具页短、测试几乎都在接近顶部操作。分页跳转加重：焦点保持 `focus()` 到分页器当前页按钮把页面滚到底部（旧 5910），scrollEnd 后软刷新在底部再跑坏舞步，永不自愈。
- 诊断手法教训：给 ScrollTrigger 打插桩日志时，日志里的 DOM 读取（scrollHeight/getBoundingClientRect/pageYOffset）会强制 flush、**意外治好被诊断的 bug**（A/B 从 −3000 变 0），必须只用局部变量日志。

## 修复（src/client/motion.ts，guardScrollTriggerMeasure，+51 行）

- ScrollTrigger 全局 `refreshInit` 事件：`scrollY !== 0` 时写内联 auto 并 `void html.offsetHeight` 强制 flush；`refresh` 事件对称清理（`active` 标记，只清自己落的值）。
- **加载窗口（y=0）必须零写入**：实测对 html 内联 scrollBehavior 的任何写入（含写回空串）都会取消浏览器待执行的片段滚动（/about/#submit 停在 0）。第一版无条件清理曾引入 5 个 e2e 回归（3×navigation hash + 2×source-filter），二分定位后收敛为对称守卫。
- 回归测试 `tests/e2e/pager-motion.spec.ts`：滚动 1600 → 点页码 2 / 输入跳 3 → 回顶再滚 → 断言 rollin 序号 + Hero transform 随滚动变化。摘除守卫 2 红、恢复 2 绿，闭环钉住。
