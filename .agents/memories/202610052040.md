## 用户反馈与修正

用户实测发现语义标签 `VIEW ↗` 会戳出圆环。量出来是确凿的：

| 标签 | 文本宽 | 圆环直径（38px × 2.3） | 结论 |
| --- | --- | --- | --- |
| `VIEW ↗`（改前） | 107.7px | 87.4px | ❌ 两侧戳出圈外 |
| `VIEW`（改后） | 71.5px | 87.4px | ✅ |
| `OPEN` | 76.7px | 87.4px | ✅ |
| `LINK` | 65.0px | 87.4px | ✅ |

修正：`data-cursor="VIEW ↗"` → `data-cursor="VIEW"`（KEntry.astro ×3、timeline-view.ts ×1），三个标签统一为四字母。**根因是标签已从圆环内移出为独立元素、不再继承圆环缩放**——原先在圆环内时文字随圆环一起放大，尺寸关系是被动成立的；移出后必须显式约束。

新增断言「语义标签完整落在圆环内」（三个内容入口逐一对齐「标签宽 ≤ 圆环直径」），三引擎实测稳定、无需容差。

**测量手法**：`label.getBoundingClientRect()` 取文本盒，`38 * DOMMatrixReadOnly(getComputedStyle(ring).transform).a` 取圆环外径（38px 是 border-box 盒宽）。严格判据是半对角线 ≤ 半径，但盒高含行高padding（34.9px，字形实际仅约 16px），过严；用「宽 ≤ 直径」既贴合"横向戳出"的视觉事实又有余量。

## 陷阱一：残留的 `astro preview` 会让 Playwright 复用旧服务，产生**假通过**

变异验证（给标签加回 `mix-blend-mode: difference`）第一次跑出 **"1 passed"** —— 假结果。原因：4321 上有残留的 `astro preview`，而 `playwright.config.ts` 的 `reuseExistingServer: !CI` 为真，测试复用了它，没有起新的服务。

清理端口后重跑，同一变异**稳定失败**并给出预期颜色 `[112,215,204]`，断言确认有牙。

**规程**：跑 Playwright 前先 `pnpm exec astro preview stop` 并确认 4321 空闲（`curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:4321/overthecocoons/` 应为 000）。

**另注**：`astro preview` 的锁是**全局单例**——我在 4323 起一个 preview 做探针，Playwright 的 webServer 就起不来（报 `Another astro preview server is already running` + `Process from config.webServer was not able to start`）。而 `astro dev`（本机跑在 4322）**不占**这个锁，可与测试并行。

## 陷阱二：「取饱和度最高像素」在红字与反相青绿之间会打成平手

标签配色用例原先 hover 标题链接取样。链接文字本身是 accent 红，光标（白 + difference）压在其上渲染成青绿 `[112,217,212]`：

- 标签字形（accent 红 `#8F262B`）通道极差 = 143 − 38 = **105**
- 光标压红字（青绿 `[112,217,212]`）通道极差 = 217 − 112 = **105**

**完全相等**（difference 是对称的），于是「极差最大者」变成抛硬币——Chromium/Firefox 抽中红字通过，WebKit 抽中青绿失败。

**修正**：取样目标换成占位版画（中心是中性底：近白底纹 + 墨色大序号），标签字形成为框内唯一高饱和像素；并另加「框内不得出现青绿像素（`G > R+30 && G >= B`）」断言，直接编码反相漂移特征，不依赖极差竞赛。

注意青绿判据不能写成 `G > B+30`：difference 出来的青绿是 `[112,215,204]`，G−B 只有 11，会漏判。
