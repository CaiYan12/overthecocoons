# 2026-10-05 20:07 — 本仓库本地开发服务器（dev）的起法与端口口径

## 结论

仓库 **没有 `dev` 脚本**（`package.json` 只有 `check` / `build` / `preview` / `test:node` / `test:e2e` / `test:e2e:matrix` / `smoke:source` / `test`）。要起开发服务器得直接调 Astro：

```
cd /d/pages/overthecocoons
cmd //c "rd /s /q D:\pages\overthecocoons\node_modules\.vite"   # 预清（见下）
pnpm exec astro dev --host 127.0.0.1 --port 4322
```

访问 `http://127.0.0.1:4322/overthecocoons/`（dev 模式同样尊重 `base`）。

## 两个必须遵守的点

1. **启动前预清 `node_modules/.vite`**：Astro dev 强制 `optimizeDeps.force=true`，vite 会无条件 `fsp.rm(node_modules/.vite/deps)`，超过沙箱 safe-delete 守卫阈值 50 就抛 `SAFE_DELETE_BULK_CONFIRM_REQUIRED` 起不来。用原生 `cmd //c "rd /s /q"` 先清掉（本次实测该目录 29 文件；清除后 dev 正常起）。**这一步必须在前台命令里做**——后台命令无法批准沙箱升级，会得到 `exit=127`。
2. **端口用 4322，不要用 4321**：4321 是 `playwright.config.ts` 里 `webServer`（`astro preview`）的端口，且 `reuseExistingServer: !CI` 为真。若 dev server 占了 4321，后续 `pnpm test:e2e` 会**静默复用 dev 服务器**而不是起 preview，测试就跑在 dev 模式上（无 prerender 产物、不同的模块加载路径），行为与结果都可能失真。

## 实测验证（真实浏览器，Chromium headless，2026-10-05）

dev 服务器确实提供 #14 的实现：`.k-cursor` 的 `mix-blend-mode: difference` 生效、dot/ring 为 `normal`、圆环 `border-top-width: 2px`、标签已移出容器（`labelParentIsCursor: false`）且 `color: rgb(143, 38, 43)`（accent）；光标点渲染 `[7,11,20]` vs 纸面背景 `[247,244,235]` → 对比度 **17.90:1**。

## 小陷阱

dev 模式下 CSS 由 vite 以 **JS 模块**注入（`<script type="module" src="/src/styles/kinetic.css">`），页面里没有 `<link rel="stylesheet">`；`curl` 该 URL 得到的是被包进 JS 字符串的 CSS，用单行正则（如 `\.k-cursor\{[^}]*\}`）grep 不到规则。**要校验 dev 提供的样式，用真实浏览器读 `getComputedStyle`，别用 curl + grep。**
