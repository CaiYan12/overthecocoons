# 2026-10-11 10:18 — 页底目录覆盖信息栏修复

## 现象与证据

- 用户截图：来源目录与底部信息栏重叠。独立Chromium1440×600复现sidebar.bottom536.3125、footer.top428.921875，重叠107.390625px；1440×900原本不重叠。
- 新页底回归先红：600px来源重叠107.390625；900px通过，证明旧高窗口检查不足。
- 原因是sticky侧栏所属grid包含页脚行，max-height仅按viewport算，允许进入页脚区域。

## 修复

- `KDocNav.astro` 外层 `data-docnav-boundary` 只占正文grid行，align-self:stretch；sticky内层原样保留。CSS原生约束包含块，无JS也不覆盖页脚。
- `doc-navigation.ts` 在吸顶且正文底边进入窗口时计算 `--docnav-boundary-height`，与原窗口max-height取min；恢复或未吸顶时移除限制，避免短内容／空主题被自身行高锁住。
- 空间不足继续原有整栏滚动兜底；footer-limit整栏模式不启动抢走全站入口的自动章节跟随，手动滚动／键盘焦点仍可到达目录。
- 手机wrapper保持原目录order与断点，取消桌面高度限制；页面内容和已GREEN的入场／退场参数保持。

## self-improvement

- 把footer放进sticky父grid可延长边界，却也会让侧栏覆盖footer自身。需要正文行的独立包含块，并用剩余真实空间限制可用高度。
- 末章入口仍可点击与页脚不重叠是两个不同断言；只测试前者会漏掉截图中的真实布局缺陷。
- 页底回归需覆盖短窗口和无JS。含scroll-behavior:smooth时，测试必须明确到达页底，不能在scrollTo后立即凭初始不重叠状态通过。
