# 2026-10-11 10:43 — 用户否决内部滚动：完整目录撑开底部

## 最新用户裁定

- 用户明确：「不要用内部滚动，视觉上不合理。直接目录把底部顶开」。这覆盖此前目录独立滚动、整栏滚动兜底、页脚限高方案，后续不得恢复旧模式。
- 保留已获用户GREEN的入场与退出动画参数；本轮只改目录布局与滚动归属。

## 实现

- 整栏与目录均移除max-height、overflow:auto及flex收缩，完整高度参与正文行布局，页脚自然排在较长一列之后。正文行边界容器保留，无重叠。
- `doc-navigation.ts` 改为仅判断完整侧栏能否放入窗口：能放下才sticky，放不下则自然文档流／整页滚动；ResizeObserver响应动态目录与字体变化。无JS默认自然流。
- 移除data-scroll-all、data-footer-limit、--docnav-boundary-height和内部章节跟随／stopFollow逻辑。没有局部scrollTop或嵌套滚动容器。
- 自然布局保留固定页头避让；仅键盘focus-visible时补偿整页焦点滚动，避免鼠标按下期间移动点击目标。
- 旧依赖局部scrollTop的导航测试按用户新裁定更新为内部scrollTop=0、整页滚动和逐项可见焦点，未削弱可达性检查。

- 修复重叠不能擅自以嵌套滚动改变视觉合同。用户明确选自然流后，应删除旧约束而非保留隐藏的内部滚动兜底。
