# 对外部 UI 分析的实测复核：我的审计 1 处误报、View Transition 缺陷实锤

时间：2026-10-06 18:00。用户转来另一 agent 的线上 UI 分析，逐条对源码+浏览器实测复核（零代码改动）。

## 三处修正（按重要性）

1. **View Transition 径向切换从未播放——缺陷实锤，机制已实测**（8ms 采样、前台窗口、线上站）：`vt.ready` 在 ~21ms resolve → `themeApplyMotion` 的 `done()` 立即摘除 `html[data-vt]`（~25ms，早于动画启动）→ `html[data-vt]::view-transition-new(root)` 规则失配，`vt-clip` 动画对象全程从未出现在 `document.getAnimations()` → 实际播放的是 UA 默认 group cross-fade（~270ms）。与该 agent 的推测方向一致（此前 30ms 采样漏掉了 21→25ms 的翻转，先得出「data-vt 全程保持」的错误中间结论——采样步长必须小于被观测事件时长）。修法：`done()` 挪到 `finished`；现有 250ms 定时器语义要拆开——ready 看门狗（挂起才 skip）与动画收尾（finished）是两件事。e2e 需补「vt-clip 出现并播放」断言（getAnimations 可观测）。
2. **我此前的审计打磨点②「k-navfoot 显示模式按钮游离」是误报**：`.mode-btn` 一直在 header（KHeader.astro:33），k-navfoot 只有「返回主站」。截图左下角的盒子是 **live-status 播报 chip**（`.live-status` fixed left/bottom、surface 底）——`announce()` 只写文本从不清除，点击主题后「显示模式：跟随系统」常驻到下一次播报。真实打磨点＝播报 chip 无自动消退。
3. **默认主题硬编码 light 成立**：BaseLayout.astro:18 `data-theme="light"`，head 脚本只恢复 localStorage 不看 prefers-color-scheme。连带解释：Playwright MCP 是持久 profile，会带上旧会话存的 dark 偏好——首轮审计看到深色由此而来，跨会话测试前先清该 origin 的 `overthecocoons.theme`。

## 其余复核（全部成立）

`data-ktrans`/`.k-transition` 死代码（全仓仅 KSite.astro 引用）；h1 全角空格 U+3000；splitChars 无 aria 处理；`.ch` 逐字符 will-change；Georgia→SimSun 合成粗体；批次时间同一分钟、哈希序定层级、Hero 每页重复、LIVE 脉动、12 主题 10 空、k-hero-en 移动端与幽灵日期同区。

## 方案立场（待用户拍板）

P0 同意全做（VT 修复是唯一真 bug）；P1「版式诚实化」方向对，但三处牵连已确认规格/语义需裁定：去序号牵连 NOW READING n/300；头条层级改「有无摘要」是展示规则（我认为合规但要落裁定记录）；空主题降权≠删除（空态是 MVP 确认决定）。P2 丝线+靛色+减动效是设计方向问题，等用户拍板；技术事实：靛色承担站内/站外是真信号；宋体子集自托管可行但要新增构建步骤；减动效与已验收的 #10–#14 冲突大，应逐项独立裁定；@view-transition navigation:auto 渐进增强可行。

## 沉淀

- 采样观测竞态类时序：步长必须 < 最短被观测事件（21→25ms 的翻转被 30ms 步长吞掉）；`document.getAnimations()` 能看到 `-ua-view-transition-group-anim-root` 但全程无 `vt-clip`＝「规则在但动画从未启动」的判据。
- Playwright MCP 持久 profile 跨会话带 localStorage 主题偏好。
- 对外部分析：逐条对源码复核而非采信；同时发现自己此前结论错时直接认错（诚实优先）。
