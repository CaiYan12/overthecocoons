## 复审抓到的 3 项真实缺陷（都已修并复核）

1. **静态分页页丢页**：`currentPage` 恒为 1，只在 `renderView` 内更新 → 从 `/page/2/` 进详情再返回，URL 仍是 `page/2/` 但渲染成第 1 页、`scrollY=0`。修法：初始化取分页器 `[aria-current="page"]` 的 `data-page`（DOM 事实，不解析 URL）。真实产物复核：返回后 `pagerCurrent=第 2 页`、`data-gi="20"`、`scrollY=1332`。
2. **减弱动态无淡入淡出**：reduced 下 `motion` 直接 `return false` 且 CSS `transition:none` → 瞬时出现，违反规格「保留轻淡入淡出」。修法：不建位移/错峰时间线，改 `data-source-fade` + CSS keyframes 只动 opacity。**实测关键**：同帧改 inline `opacity` 拿不到可过渡起点（0 个中间帧，computed 直接是 1），必须用 keyframes。复核：5 帧淡入 + 5 帧淡出、位移恒 0、选项无错峰。
3. **初始化失败成死按钮**：`index.ts` 无条件调 `initSourceFilter`，数据岛损坏时 `initTimeline` 提前 return，入口仍被 `<a>`→`<button>` 替换，`applySources` 被静默吞掉。修法：`SourceFilterHost.ready()`，未就绪直接返回。复核：数据岛损坏 → 1 个 `<a>`/0 个 button、href 正确、点击真导航 `/sources/`。

另修：移动 WebKit `dialog.close()` 随焦点产生 +7px 滚动偏移（实现内复位 + e2e 守住）；滚动条 CSS 两条规则被误合并导致 `top`/`z-index` 失效（还原两行）。

## 经验（可复用）

- **`scrollIntoView({behavior:"auto"})` 会沿用 CSS `html{scroll-behavior:smooth}`**：需要即时定位时必须显式 `"instant"`。实测 Firefox 上平滑滚动会被 `ScrollTrigger.refresh` 打断，停在半途（离读线 263px）。
- **减弱动态的淡入淡出不能用「同帧改 inline opacity」实现**：浏览器没有可过渡起点，computed 值直接跳到终值（0 个中间帧）。必须用 CSS keyframes 或先设置初值再在下一帧改。
- **Playwright headless 拿不到 BFCache**（`pageshow.persisted` 恒 false），即使 `ignoreDefaultArgs: ["--disable-back-forward-cache"]`；headful + 该参数才能命中。headful 可用 `--window-position=-3000,-3000` 移出屏幕避免打扰。
- **Astro preview 的锁文件按项目根唯一、不按端口**：同项目第二个 preview 实例必须 `--ignore-lock`。
- **探针自身会有竞态**：验证「应用后状态」必须先严格等待应用生效（断言入口文案/总数变化），否则会读到旧状态并误判为产品缺陷。本次我因此先误报过一次「BFCache 状态不一致」。
- **验收标准 checkbox 必须按实证勾选**：文档声称「已证明」的项若没有对应用例（如 MENU 互斥），属于虚报，复审会抓到。
- **不要用整套测试矩阵验证单点失败**：先 `-g` 定向复跑，最后再跑一次矩阵。本次在矩阵上多花约 15–20 分钟无效时间。
